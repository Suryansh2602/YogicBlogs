# API Reference

REST + JSON API served by `backend/`. The frontend (and Postman) are the only clients.

- **Base URL:** `http://localhost:5000/api/v1` (dev), `https://api.healthmarg.com/api/v1` (prod)
- **Postman:** import `backend/postman/healthmarg.postman_collection.json` and `backend/postman/local.postman_environment.json`. The collection is updated with every API change.
- **Status legend:** ✅ built · 🔜 planned (phase in [plan.md](plan.md))

---

## 1. Conventions

### Requests
- `Content-Type: application/json` for every body (planned: other types get `415`). Max body is 100 kB (admin article saves will allow 1 MB).
- Exception: media uploads are `multipart/form-data` (only on `POST /admin/media/images`). No other route parses multipart, so HTML-form CSRF payloads are never read.
- Unknown fields are rejected (`zod .strict()`), so mass-assignment such as sending `"role": "admin"` fails with `400`.
- IDs are UUID v7 strings. Public URLs use slugs.

### Authentication ✅
| Credential | Where | Sent to |
|---|---|---|
| Access token (JWT, 15 min) | `Authorization: Bearer <token>` | Every protected endpoint |
| Refresh token | `HttpOnly; SameSite=Strict` cookie `hm_rt` (`__Secure-hm_rt` in production), `Path=/api/v1/auth` | Only `POST /auth/refresh` and `POST /auth/logout` |
| CSRF token | `X-CSRF-Token` header (from `GET /auth/csrf`), plus an allowed `Origin` | Cookie endpoints only |

### Responses
Success returns the resource directly, or `{ data, page }` for lists.

Errors always have this shape:
```json
{ "error": { "message": "Validation failed", "code": "VALIDATION_FAILED", "details": [{ "path": "email", "message": "Invalid email" }] } }
```
Messages are safe to show users. Internals (SQL, stack traces, hosts) are never returned.

One **global error handler** produces every error ✅ ([error-pages.md](error-pages.md)):
- **Every error has a `code`.** When a route doesn't set one, it is filled in from the status: `BAD_REQUEST`, `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `GONE`, `PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `UNPROCESSABLE`, `RATE_LIMITED`, `INTERNAL_ERROR`, `SERVICE_UNAVAILABLE`. Broken JSON is `INVALID_JSON`.
- **Every response has an `X-Request-Id` header**: a random ID, generated by the server (one sent by the client is ignored). It is used in logs and the audit log.
- **Server errors (5xx) carry `reference`**, the same request ID, so a reader can quote it and the log entry can be found:
```json
{ "error": { "message": "Something went wrong on our side. Please try again.", "code": "INTERNAL_ERROR", "reference": "0190a1b2-c3d4-7000-8000-00000000f00d" } }
```
- **MySQL or Redis unreachable** (refused connection, pool or lock timeout, closed Redis client): `503 SERVICE_UNAVAILABLE` with `Retry-After: 30`.

| Status | Meaning |
|---|---|
| 200 / 201 / 204 | OK / created / no content |
| 202 | Accepted. Used where the answer must not reveal whether an email exists (register, forgot password). |
| 400 | Invalid input (`details` lists fields) |
| 401 | Not signed in / token invalid or expired |
| 403 | Signed in but not allowed (wrong role, 2FA required, CSRF failed) |
| 404 | Not found, also used instead of 403 when revealing existence would leak information |
| 409 | Conflict (duplicate slug, stale `version` on save) |
| 411 | Upload without a `Content-Length` (`LENGTH_REQUIRED`; browsers always send one) |
| 413 / 415 | Body too large / wrong content type (uploads: `FILE_TOO_LARGE` / `UNSUPPORTED_FILE_TYPE`) |
| 422 | Upload understood but unusable (`IMAGE_TOO_LARGE` in pixels, `IMAGE_TOO_COMPLEX` over the 30 s processing limit, `IMAGE_UNREADABLE`) |
| 507 | Server storage almost full: uploads paused (`STORAGE_FULL`) |
| 429 | Rate limited (`RateLimit` + `Retry-After` headers) |
| 503 | A dependency (MySQL/Redis) is unavailable, or the image processor is busy (`BUSY` + `Retry-After`) |

### Pagination 🔜
Cursor-based: `?limit=20&cursor=<opaque>` returns `{ "data": [...], "page": { "nextCursor": "..." | null } }`. `limit` is capped at 50.

### Rate limits ✅
| Scope | Limit | Store |
|---|---|---|
| Every request, per IP | 300 / 15 min | Redis (fails open) |
| Credential endpoints, per IP (login, register, 2FA, reset, verify, admin setup) | 30 / 15 min, shared | Redis (fails closed) |
| Login failures, per IP + account ✅ | 5 / 15 min → locked 15 min (`429 LOGIN_LOCKED`) | Redis |
| Login failures, per account ✅ | 20 / hour → locked 1 h | Redis |
| Image uploads, per admin ✅ | 60 / hour (`429 UPLOAD_LIMIT`) | Redis (fails closed) |
| Public images, per IP ✅ | 1500 / 15 min, instead of the general limit | Redis (fails open) |
| Browser error reports, per IP ✅ | 20 / 15 min | Redis (fails open) |

Rate-limited answers are `429` with `code: "RATE_LIMITED"`. `/auth/csrf`, `/auth/refresh` and `/auth/logout` run on page loads, so only the general limit applies to them.

Headers follow the IETF draft-8 standard (`RateLimit`, `RateLimit-Policy`).

## 2. Health ✅

### `GET /health`
Public. Reports whether dependencies are reachable, and never reveals versions, hosts or errors.

`200`
```json
{ "status": "ok", "database": "up", "redis": "up" }
```
`503`
```json
{ "status": "degraded", "database": "up", "redis": "down" }
```

### `POST /client-errors` ✅
Public. The website's global error handler reports an error that happened in a visitor's browser, so we hear about crashes. It is logged only (at `warn`), never stored in the database.

```json
{ "kind": "crash", "message": "Cannot read properties of undefined", "path": "/articles/calm", "reference": "0190a1b2-c3d4-7000-8000-00000000f00d" }
```
- `kind`: `crash` | `unhandled` | `updated` | `offline` | `api`.
- `message`: 1–300 characters. `path`: up to 500 characters.
- `reference`: optional; the API's request ID when the error came from an API response.
- Unknown fields are refused, so a stack trace or cookies can't be sent.
- No personal data is kept: only the address path (query strings and fragments, which can carry reset or sign-in tokens, are removed), and emails and token-like strings in the message are blanked out.

`204` · `400 VALIDATION_FAILED` · `429 RATE_LIMITED` (20 per 15 minutes per IP)

## 3. Auth ✅ (Google sign-in and session management 🔜)

Credential endpoints use the strict rate limit. Steps marked 🤖 require a reCAPTCHA v3 token (`captchaToken` in the body) when `RECAPTCHA_MODE=live` (always in production; `off` locally).

> **Email features are switched off for now** (`EMAIL_ENABLED=false` on the API, `VITE_FEATURE_EMAIL=false` on the frontend; owner decision 2026-10-25). While off:
> - `POST /auth/register` answers **`201` with a session** (signed in at once, refresh cookie set), or **`409 EMAIL_TAKEN`** (`details[0].path = "email"`) for a registered email.
> - Login does not require a confirmed email.
> - `/auth/verify-email`, `/auth/verify-email/resend`, `/auth/password/forgot` and `/auth/password/reset` are **not mounted (404)**, and no emails are sent.
>
> Trade-off while off: sign-up reveals whether an email is registered (rate limits slow down probing). Turning both flags on restores everything below, including the silent `202`.

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/auth/csrf` | — | Issue a CSRF token for the cookie endpoints |
| POST | `/auth/register` 🤖 | — | Create account → always `202`, verification email sent |
| POST | `/auth/verify-email` | — | `{ token }` → marks email verified |
| POST | `/auth/verify-email/resend` 🤖 | — | Always `202` |
| POST | `/auth/login` 🤖 | — | Password login → session, or a 2FA challenge |
| POST | `/auth/admin/login` 🤖 | — | Same, for the `/admin` page: non-admins get the generic `401` |
| POST | `/auth/login/2fa` | ticket | `{ mfaTicket, code }` (6-digit TOTP or backup code). 5 wrong codes burn the ticket |
| POST | `/auth/login/2fa/setup` | ticket | Admin's first sign-in: `{ mfaTicket }` → `{ otpauthUrl, qrDataUrl, secret }` |
| POST | `/auth/login/2fa/enable` | ticket | `{ mfaTicket, code }` → session + `backupCodes` (shown once) |
| POST | `/auth/refresh` | cookie + CSRF | Rotate the refresh token, get a new access token |
| POST | `/auth/logout` | cookie + CSRF | End this session |
| POST | `/auth/logout-all` | Bearer | End every session (bumps `token_version`) |
| POST | `/auth/password/forgot` 🤖 | — | Always `202` |
| POST | `/auth/password/reset` | — | `{ token, password }` → all sessions revoked |
| POST | `/auth/2fa/setup` | Bearer | Returns `{ otpauthUrl, qrDataUrl, secret }` (pending until enabled); `409` if already on |
| POST | `/auth/2fa/enable` | Bearer | `{ code }` → enables 2FA, returns backup codes once |
| GET | `/auth/google/start` 🔜 | — | Redirect to Google (PKCE, state, nonce) |
| GET | `/auth/google/callback` 🔜 | — | Google redirects here; never call it directly |
| POST | `/auth/2fa/disable` 🔜 | Bearer + recent auth | Not allowed for admins (2FA is mandatory) |
| POST | `/auth/2fa/backup-codes` 🔜 | Bearer + recent auth | Regenerate (old codes stop working) |
| GET | `/auth/sessions` 🔜 | Bearer | List my active sessions (device, IP, last used) |
| DELETE | `/auth/sessions/:id` 🔜 | Bearer | Revoke one session |

**`POST /auth/register`**
```json
// request
{ "email": "asha@example.com", "password": "correct horse battery staple", "displayName": "Asha",
  "acceptTerms": true, "acceptPrivacy": true, "captchaToken": "..." }
// 202 — same response whether or not the email already exists
{ "message": "If the details are valid, we’ve sent you an email with the next step." }
```

**`POST /auth/login`**
```json
// request
{ "email": "asha@example.com", "password": "...", "captchaToken": "..." }
// 200 — no 2FA: refresh cookie set, access token in the body
{ "accessToken": "eyJ...", "user": { "id": "0190...", "email": "asha@example.com", "displayName": "Asha", "role": "user",
  "avatarUrl": null, "emailVerified": true, "twoFactorEnabled": false, "createdAt": "..." } }
// 200 — 2FA on: no session yet, send the code to /auth/login/2fa
{ "mfaRequired": true, "mfaTicket": "opaque-random" }
// 200 — admin without 2FA: must enrol first (/auth/login/2fa/setup → /enable)
{ "mfaSetupRequired": true, "mfaTicket": "opaque-random" }
// 403 — correct password but email not confirmed
{ "error": { "message": "Please confirm your email first. We can send the link again.", "code": "EMAIL_NOT_VERIFIED" } }
// 401 — same message for unknown email and wrong password
{ "error": { "message": "The email or password is incorrect. Check both and try again.", "code": "INVALID_CREDENTIALS" } }
```

Password rules: 12–128 characters, must not contain your email name or display name, must not be one repeated character, checked against known-breached passwords (HIBP k-anonymity), hashed with argon2id.

**Error messages say exactly what is wrong.** Examples: `Your password has 8 characters. Use at least 12.`, `“gmail” isn’t a complete domain. It needs an ending like .com or .in.`, `This password has appeared 21,613 times in leaked password lists…`, `That code didn’t match… 3 tries left.` Field problems come in `details[{ path, message }]`, and `message` repeats the first one.
- **Two deliberate exceptions, for security:** a failed sign-in never says whether the email or the password was wrong, and sign-up, resend and forgot-password never say whether an account exists.
- **Waiting times:** `429` answers carry `Retry-After` (exposed to the browser via CORS), so the page can say how long to wait.

**Error codes** the frontend reacts to: `INVALID_CREDENTIALS`, `EMAIL_NOT_VERIFIED`, `ACCOUNT_SUSPENDED`, `LOGIN_LOCKED`, `RATE_LIMITED`, `CAPTCHA_FAILED`, `WEAK_PASSWORD`, `BREACHED_PASSWORD`, `INVALID_TOKEN` (email link), `INVALID_CODE`, `MFA_TICKET_INVALID`, `TOKEN_INVALID` / `TOKEN_REVOKED` / `NO_TOKEN` (sign in again), `NO_SESSION` / `SESSION_EXPIRED` / `SESSION_REVOKED` (refresh failed), `CSRF_FAILED`.

**Refresh reuse interval:** a refresh token rotated less than 10 s ago can be exchanged once more for a fresh token in the same session. This covers a page reload or second tab racing the refresh, or a lost reply. It never applies after sign-out, password reset or detected theft. Reuse after 10 s is treated as theft: the session is revoked (`SESSION_REVOKED`). Older API versions answered `409 REFRESH_RACE` here; the frontend still retries once if it sees it.

## 6. Admin dashboard (✅ setup, stats, users, audit, conditions, media, articles)

**First admin (bootstrap).** There is no public admin sign-up. While no admin exists:

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/admin/setup/status` ✅ | — | `{ setupRequired: true or false }` |
| POST | `/admin/setup` ✅ | setup code | `{ setupCode, email, password, displayName }` → `201 { user }`. `403 SETUP_CODE_INVALID`; `409 SETUP_CLOSED` once an admin exists |

The setup code is `ADMIN_SETUP_CODE` from the server environment or, if unset, a one-time code printed to the server log at startup. The new admin enrols 2FA at first sign-in.

Every other admin endpoint requires: `Bearer` → role `admin` → **2FA used for this session** (`403 FORBIDDEN` / `MFA_REQUIRED`). Every change writes an audit log entry.

| Method | Path | Purpose |
|---|---|---|
| GET / POST | `/admin/conditions` ✅ | List all with `articleCount` / create `{ name, slug?, summary?, description?, sortOrder?, isPublished? }`. The slug is made from the name when omitted (`400 SLUG_REQUIRED` for names with no English letters). Duplicates → `409 NAME_TAKEN` / `SLUG_TAKEN` with `details[0].path` |
| PATCH / DELETE | `/admin/conditions/:id` ✅ | Edit any field / soft delete (`409 CONDITION_IN_USE` with the count while articles use it). A deleted condition's name and slug can be reused |
| GET / POST | `/admin/articles` ✅ | List (`status`, `conditionId`, `q` over draft titles) / create `{ title, conditionId, accessLevel?, lang? }` |
| GET | `/admin/articles/:id` ✅ | Draft, `draftVersion`, live state, outbound links with each target's state, inbound count, checklist |
| PUT | `/admin/articles/:id/draft` ✅ | Autosave `{ draftVersion, draft }` (up to 1 MB; 600 per 15 min per admin) → `409 STALE_VERSION`, `410 ARTICLE_DELETED`, `400 INVALID_DOCUMENT` |
| GET | `/admin/articles/:id/checklist` · `/preview` ✅ | Publish checklist / the draft as readers would see it |
| POST | `/admin/articles/:id/publish` ✅ | `{ draftVersion }` → live = draft (`422 PUBLISH_CHECKLIST` lists every problem) |
| POST | `/admin/articles/:id/unpublish` · `/archive` ✅ | `{ confirm? }` (`409 HAS_INBOUND_LINKS` while published articles link here) |
| POST | `/admin/articles/:id/discard-draft` ✅ | `{ draftVersion }`: back to the published copy |
| DELETE | `/admin/articles/:id` ✅ | `{ draftVersion, confirm? }`: soft delete |
| GET / POST | `/admin/articles/:id/revisions[/:revisionId[/restore]]` ✅ | List (no snapshots) / one snapshot / save one / restore `{ draftVersion }` |
| POST | `/admin/media/images` ✅ | Multipart: one `file` (JPEG/PNG/WebP; an animated PNG uses its first frame; ≤ `MAX_IMAGE_MB`, default 15) + optional `altText` (≤ 255). The type is read from the bytes, never the name. Re-encoded to WebP at 480/960/1600 px (never upscaled) without EXIF/GPS, plus a blurred placeholder → `201 { media, deduplicated: false }`; the same file again → `200 { media, deduplicated: true }` (its `altText` fills in a missing one, never replaces one; still audited). Errors: `400 NO_FILE / UPLOAD_INVALID / UPLOAD_ABORTED / VALIDATION_FAILED`, `411 LENGTH_REQUIRED`, `413 FILE_TOO_LARGE` (checked from `Content-Length` before reading; the connection is then closed), `415 UNSUPPORTED_FILE_TYPE` (names the real type), `422 IMAGE_TOO_LARGE` (over 10 000 px a side or 40 MP) / `IMAGE_TOO_COMPLEX` / `IMAGE_UNREADABLE`, `429 UPLOAD_LIMIT`, `503 BUSY`, `507 STORAGE_FULL` |
| POST | `/admin/media/audio` | Upload audio (multipart) |
| GET | `/admin/media?kind=&page=&pageSize=` ✅ | Newest first → `{ items, page, pageSize, total, limits: { maxImageMb } }` (the admin page checks files against `limits`); each item: `{ id, kind, status, altText, width, height, sizeBytes, originalName, placeholder, variants: [{ width, height, url }], createdAt }` (`url` is relative to `/api/v1`) |
| PATCH / DELETE | `/admin/media/:id` ✅ | `{ altText }` → `{ media }` / soft delete + files removed (`409 MEDIA_IN_USE` with `details: { articles, conditions }` while an article cover/audio or condition hero uses it). Use inside article bodies is checked from branch 3 |
| GET | `/admin/users?page=&pageSize=&search=&role=` ✅ | Search by email or name → `{ items, page, pageSize, total }` |
| GET | `/admin/users/:id` | User detail + sessions |
| PATCH | `/admin/users/:id` | `{ status }`: suspend or reactivate (revokes sessions) |
| PUT | `/admin/users/:id/role` | Change role (recent auth; can't demote yourself or the last admin) |
| POST | `/admin/users/:id/revoke-sessions` | Force logout everywhere |
| POST | `/admin/users/:id/reset-2fa` | Reset another user's 2FA (never your own) |
| GET | `/admin/audit-logs?page=&pageSize=&action=` ✅ | Newest first; `action` is a prefix such as `auth.` or `admin.setup` (more filters 🔜) |
| GET | `/admin/stats` ✅ | `{ users, admins, verified, suspended, newThisWeek, activeThisWeek }` (articles and reads 🔜) |
